# UI デザイン方向づけ(v0.1)

- 対応要件: [要件定義書](../requirements.md) §10 ビジュアルデザイン方針(事務的にしない・毎日使って楽しい・ビビッドCMYK基調・AA準拠)
- 対象画面: ログイン / 打刻(ホーム) / 月次

## コンセプト: 印刷所の刻印

KIZAMI の世界観を**印刷プロセス**に置く。打刻=スタンプ(刻印)、CMYK=プロセスインキ、
打刻列=トンボ(見当合わせマーク)、月次集計=インキ濃度。
「毎日押すことが楽しい」の中心は打刻ボタンの**刻印演出**にあり、それ以外は静かに保つ
(遊びは日常接点のみ・締め/承認系は明瞭優先、という要件の実装)。

## カラートークン

インキ原色は塗り・大型要素専用。テキストには AA を満たす ink 変種を使う(色のみに意味を持たせない)。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--k-paper` | `#FBFBF9` | 地。クールな紙白(クリーム系は使わない) |
| `--k-key` | `#1A1A1A` | K。本文・枠線・主要 UI |
| `--k-ink-soft` | `#55565A` | 二次テキスト |
| `--k-cyan` | `#00A3D9` | 出勤系の塗り・マーク |
| `--k-cyan-ink` | `#006E99` | 出勤系のテキスト・アイコン線(AA) |
| `--k-magenta` | `#E5007E` | 退勤系の塗り・マーク |
| `--k-magenta-ink` | `#B80065` | 退勤系のテキスト(AA) |
| `--k-yellow` | `#FFD400` | 休憩系の塗り・ハイライト。**テキスト使用禁止** |
| `--k-yellow-ink` | `#8A6D00` | 休憩系のテキスト(AA) |

意味づけ(常にラベル・アイコンを併記): 出勤=C、休憩=Y、退勤=M、地とテキスト=K。
ダーク対応は v0.1 スコープ外(トークン設計だけ崩さないこと)。

## ロゴとアイコン(2026-08-22 確定)

「印刷所の刻印」のコンセプトを、ロゴマークと文字ロゴそれぞれに落とし込んだ確定版。
**形状・色・針の角度は変更禁止**(再検討はスコープ外)。

### マーク: トンボ(見当合わせマーク)+ 時計の針

確定ソース: `apps/web/public/icons/source/kizami-mark.svg`(64x64 viewBox)。

```svg
<svg viewBox="0 0 64 64" xmlns="http://www.w3.org/2000/svg">
  <g stroke-width="3" fill="none" stroke-linecap="square">
    <line x1="32" y1="4"  x2="32" y2="18" stroke="#1A1A1A"/>
    <line x1="60" y1="32" x2="46" y2="32" stroke="#00A3D9"/>
    <line x1="32" y1="60" x2="32" y2="46" stroke="#E5007E"/>
    <line x1="4"  y1="32" x2="18" y2="32" stroke="#FFD400"/>
    <circle cx="32" cy="32" r="16" stroke="#1A1A1A"/>
  </g>
  <g stroke="#1A1A1A" stroke-width="3" stroke-linecap="round">
    <line x1="32" y1="32" x2="41.5" y2="26.5"/>
    <line x1="32" y1="32" x2="41.5" y2="37.5"/>
  </g>
</svg>
```

**由来**: トンボ(印刷の版ズレを合わせる印)と時計の文字盤・針を重ねる。4本の腕が CMYK の
4版に対応し、**12時の腕が K(黒)、そこから右回りに C(3時)→M(6時)→Y(9時)**。針は
**1時方向と5時方向**を指すが、これは装飾ではなく「K」の字の開き方(縦棒+開いた斜め2画)に
由来する角度で、中央の円 = 時計の文字盤 = トンボの円という三重の意味を持たせている。

**サイズ別の調整**(小さいほど線を太く、腕をわずかに外へ伸ばす): 192px 以上は
`stroke-width` 3 のまま(確定ソースそのもの)。44〜96px 相当(実際に画面上で見える
物理サイズ基準。ファイルが 180px の apple-touch-icon もここに含む=判断点)は
`stroke-width` 4。32px 以下(favicon)は `stroke-width` 5 かつ腕の外端をさらに外へ
伸ばす(例: 上腕 `y1="2"`、右腕 `x1="62"`)。`apps/web/src/components/KizamiMark.tsx`
と `scripts/generate-icons.mjs` は同じ3段階のバケット判定を共有している。

**ダーク対応**: K に相当する部分(12時の腕・円・針)の `#1A1A1A` を `#F2F2EE` に
置き換えるだけ。CMYK の3色は固定色のまま変えない。`favicon.svg` は
`@media (prefers-color-scheme: dark)` を SVG 内に埋め込んで対応し、アプリ内
(`KizamiMark` コンポーネント)は `currentColor` を使ってテキスト色に追従させる。

**マスカブル版**(Android、`icon-maskable-512.png`): 安全領域(中央80%)に収まるよう
確定マークを 0.8 倍に縮小し、背景を `--k-paper`(`#FBFBF9`、紙白)で塗る。
`apple-touch-icon.png` / `icon-192.png` / `icon-512.png` も透過だと表示環境によって
見え方が不安定になるため、同じ紙白背景を敷いている(独自判断)。`favicon.svg` /
`favicon-32.png` はブラウザタブ上にそのまま浮かせるため背景なし(透過)。

### 再生成の手順

`apps/web/public/icons/source/kizami-mark.svg` をソース・オブ・トゥルースとして、
`node scripts/generate-icons.mjs`(要 `rsvg-convert`)を実行すると以下を再生成する:

- `apps/web/public/favicon.svg`・`favicon-32.png`・`apple-touch-icon.png`
- `apps/web/public/icons/icon-192.png`・`icon-512.png`・`icon-maskable-512.png`
- `docs/public/kizami-mark.svg`(VitePress の `themeConfig.logo` 用。`favicon.svg` と同一内容)

形状そのものを変える場合は `scripts/generate-icons.mjs` の `markGroups()` を直接編集する
(座標をハードコードしているのは意図的 — 確定形状を1箇所からしか変えられないようにするため)。

### 文字ロゴ: Jost

Google Fonts の **Jost**(Futura の流れを汲む幾何学サンセリフ)を採用。トンボの造形と
同じ「円と直線」の語彙で揃えている。ウェイトは **500**、字間は **0.18em** と広めに取り、
製図的な精度感を出す。CSS 変数 `--font-logo`(`tokens.css`)としてロゴ専用に切り出し、
ヘッダー(`.k-header__logo`)とログインカード(`.login-card__logo`)で共有する。

**状態スタンプの書体(`--font-display` = Shippori Antique B1)は変更していない**。
ロゴは製図・見当合わせという「精度」のモチーフ、スタンプは活版印刷という「刻印」の
モチーフで、担っている役割が異なる。スタンプ側の活版の趣を保つことは v0.1 の
コンセプト(「打刻=スタンプ(刻印)」)の核であり、ロゴ書体の変更に巻き込まない。

## 画面設計

### 打刻(ホーム)= 今日の一枚

```
┌────────────────────────────┐
│ KIZAMI            [user ▾] │
│                            │
│        12:34               │  ← 現在時刻(Plex Mono、大)
│      ┌────────┐            │
│      │ 勤務中 │            │  ← 状態スタンプ(円形印影、わずかに回転、
│      └────────┘            │     CMYK版ズレ風の影)
│                            │
│  [出勤]  [休憩]  [退勤]   │  ← インキパッド風の大ボタン(状態で活性制御)
│                            │
│  ──┼──C──Y─Y──M────────── │  ← 今日のトンボ列(打刻チップ、時刻ラベル付き)
└────────────────────────────┘
```

- **シグネチャ演出(一点豪華)**: 打刻ボタン押下時、CMYK 4版がわずかにズレて現れ
  ピタッと見当が合って「刻まれる」スタンプアニメーション(300ms 程度)。
  `prefers-reduced-motion` では即時表示に置き換える
- 版(C/Y/M)はボタンの**塗り色でのみ**示し、文字ラベルは付けない。単独のアルファベットはキーボードショートカットと誤読される(2026-08-21 レビューで削除)
- 状態遷移で押せないボタン(勤務外の退勤など)は disabled + 理由をツールチップではなく
  ラベル下の小さな文言で(自明な操作にヘルプは付けない原則の範囲で最小限)
- 打刻成功のフィードバックはトンボ列への追加アニメーションで示す(トーストは出さない)

### 月次

- K 主体の静かなテーブル。日付・勤務・実労働・休憩・深夜・警告
- フレックス収支は**インキ濃度バー**(枠に対する使用量を C の網点濃度で表現、数値併記)
- 警告のある日は Y のマーク+文言(色のみ禁止)
- 区分別合計はチップ(C/M/Y/K の枠色+ラベル)

#### 打刻時刻と制度による列の出し分け(2026-08-23 決定)

**勤務列**は出勤と退勤を1セルにまとめる(`9:00 → 18:30`)。2列に割ると横幅を食うわりに、
読み手はほぼ常に「いつからいつまで」を対で見るため。

- 日界をまたぐ退勤は `22:00 → 翌 7:00` と表記する。時刻だけ出すと前日の勤務が消えて見える
- 未退勤は `22:00 → —`(警告列にも出るが、勤務列だけ見ても気づける必要がある)
- 中抜けで区間が複数ある日は全区間を積んで表示する。件数バッジに畳むと、
  中抜けの有無という**修正申請の判断に効く情報**が隠れてしまう

**時間外列はフレックスでは出さない。** 法律上その日には決まっていないため
([work-systems.md](./work-systems.md))。列を出して 0 を並べると「時間外なし」という
誤った理解を与える。列の有無という一番強い手掛かりで制度の違いを示し、
テーブル見出しに `attendance.work-system` の HelpTip を添えて理由に到達できるようにする。

固定時間制の時間外セルは**法定時間外を主表示**とし、法定内残業があればその下に小さく併記する
(`1:00` / `法定内 0:30`)。割増の要否が違う二つの数字を同じ大きさで並べない。

フレックス収支バーは固定時間制では出さない(`flexBalance` が `null`)。
代わりにその位置へ時間外の月合計を置き、36協定の月45時間に対する位置を同じインキ濃度バーで示す。
バーの意味(枠に対する進捗)が制度をまたいで一貫する。

## ガイド・ヘルプの方針(2026-08-22 決定)

法令に詳しくない労務担当者と、制度を知らない従業員の**両方**が判断を誤らないよう導くことを、
本製品の価値の一部とする(正しく計算するだけでは足りない)。

### 出所を必ず区別する

表示するすべての説明に、以下のいずれかのラベルを付ける。混ぜると、法定要件を社内ルールだと
誤認して緩めたり、社内ルールを法定だと思い込んだりする。コンプライアンス製品として最も危険な失敗。

| ラベル | 意味 | 変更可否 |
| --- | --- | --- |
| **法令** | 労基法○条等に基づく要件 | 変更不可(`@kizami/law` が根拠を持つ) |
| **KIZAMIの仕様** | このシステムの挙動・設計判断 | バージョンで変わる |
| **自社の規定** | その会社が定めたルール | テナントが編集する |

### 出し分け

同じ知識源(`packages/help-content`)から、立場と文脈に応じて出す。

| 出し方 | 対象 | 例 |
| --- | --- | --- |
| その場の一言 | 全員 | 残高の横に「取得期限は付与から2年です」 |
| 気づきの通知 | 従業員本人 | 「有給が3日分、あと2ヶ月で失効します」 |
| 申請時の助言 | 従業員本人 | 「半休は年5日義務にカウントされます。時間単位はされません」 |
| 設定時の注意 | 労務担当者 | 「この変更は適用開始日以降に効き、過去の集計は変わりません」 |
| 解説記事 | 両方 | VitePress の「有給休暇のしくみ」 |

### 「なぜこの数字か」の開示

集計結果には根拠を添える(例: 総枠177:08 の横に「週40時間 × 暦日数 ÷ 7(労基法32条)」)。
従業員が自分の労働時間を自分で検算できる状態にし、「会社が計算した数字を受け取るだけ」の
非対称を減らす。`@kizami/law` が根拠条文をデータとして持っているため実現できる。

### 社内規定の併記

- アプリ内: `help_overrides`(tenant × ヘルプキー)で組み込みの説明に自社の追記を足せる。
  就業規則へのリンク設定も持つ
- ドキュメント: `docs-local/` オーバーレイをビルド時にマージし「社内規定」セクションに出す。
  フォーク不要でアップグレードと衝突しない(セルフホスト OSS としての要件)

### 社内規定の記入例(テンプレート)

空欄と「ここに社内規定を書いてください」だけでは担当者は何を書けばよいか分からない。
ヘルプキーごとに**記入例**を持たせ、編集画面にプレースホルダとして薄く表示する。

| ヘルプキー | 記入例 |
| --- | --- |
| 有給の申請 | 「申請は取得日の前日までにお願いします」「繁忙期(12月)は1週間前までにご相談ください」 |
| 時間単位年休 | 「1回あたり2時間単位で取得できます(労使協定による)」「上限は年3日分です」 |
| 打刻忘れ | 「打刻を忘れた場合は、翌営業日中に修正申請を出してください」 |
| 締め | 「毎月5日に前月分を締めます。それまでに修正申請を完了してください」 |
| 直行直帰 | 「直行直帰の場合は、事前に上長へ連絡のうえ現地で打刻してください」 |

**書き方のガイドライン**(編集画面に併記する):

1. **法令の内容は書き写さない** — 法令部分は自動で表示される。重複させると、法改正で
   KIZAMI 側だけが更新され、社内規定欄に古い記述が残って矛盾する
2. **自社で決めたことだけを書く** — 期限・窓口・例外の扱いなど
3. **就業規則の該当条文を参照する**形が望ましい(「詳細は就業規則第○条」)

「何を書かないか」を示すことが、記入例の最も重要な役割である。

### 個人情報まわりの雛形(2026-08-22 決定)

KIZAMI 自身に OAuth のためのプライバシーポリシーは不要(KIZAMI は OIDC クライアントであり、
導入企業が自社の IdP に Internal/シングルテナントでアプリ登録するため、Google の審査も
ポリシー URL も要求されない)。

一方、**打刻記録・IP・UA・GPS 座標は従業員の個人情報**であり、個人情報保護法上の義務
(利用目的の特定・公表、GPS 取得時の明示)を負うのは**導入企業**である。セルフホスト OSS では
個人情報の管理者は導入企業であって KIZAMI プロジェクトではないため、KIZAMI の責任範囲は
「導入企業が義務を果たせるよう支援すること」になる。

同梱する雛形:

- **従業員向けプライバシー通知** — 取得項目(打刻・IP・UA・GPS)、利用目的、保存期間
- **利用規約(社内向け)** — 正確な打刻の義務、代理打刻の禁止など
- **設定に応じた自動生成** — GPS が無効なら該当項を出さない、保持期間はテナント設定値を埋める

将来ホスト版(SaaS)を提供する場合は、提供者自身が個人情報の管理者になるため、
プライバシーポリシーと利用規約が別途必須になる。
